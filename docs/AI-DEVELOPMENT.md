## AI 做了什么，作者做了什么

本游戏从最初的网页版联机原型到当前版本，程序代码、玩法实现、UI、程序动画、联机协议、测试、说明文档和打包发布工作，均由 AI 编程代理在作者持续提出需求、试玩与反馈的过程中完成。作者负责产品方向、玩法取舍、体验验收、账号与发布授权，并提供咖啡赞助收款码。项目使用 Phaser、React、Socket.IO、Electron 等已有开源技术；AI 的实现工作建立在这些引擎与库之上。美术来源、生成与加工流程见 [美术说明](ART-3.4.md) 和 [第三方声明](../THIRD_PARTY_NOTICES.md)。

这份文档记录可核验的工作流程和设计变化。早期迭代依据作者提供的需求对话整理；公开 Git 历史从首次上传时开始，无法展示此前每一次本地修改。下文的实施解释是事后整理，原始需求摘录与可复用提示词分别标注。

## 3.8 品牌修正与作者反馈

作者随后将标题方向调整为“摸到鱼才是自己挣到的”，游戏更名为「薪水小偷 / Salary Thieves」。大标题为“班是公司的，鱼是自己的。”，副标题为“摸到的鱼，才算自己挣到的。”。作者明确二维码放在GitHub，AI因此撤下游戏内的咖啡面板，将原图迁到文档目录，供README与支持页面展示。

发布使用作者本机已有的GitHub CLI登录授权，由系统凭据存储保管；CI使用GitHub Actions自动提供的GITHUB_TOKEN发布镜像与附件。本次本地Git TLS中断后，通过同一授权调用Git Data API，并核对源码树、提交与标签对象SHA与本地完全一致。

## 一轮实际开发如何进行

1. **把体验问题变成可观察现象。** 例如“攻击不明显”要检查当前真正显示的模型，不能只确认服务器伤害增加。
2. **追踪完整数据路径。** 输入 → 服务端动作开始 → 延迟释放伤害 → 网络快照 → 客户端连续动作 → 武器握持、轨迹与命中反馈。
3. **记录假设与验收条件。** 在本地规划文件中记录发现，先增加能失败的回归。普攻要覆盖全部职业，并验证不占改装槽、不替换 Q、重开与中途加入仍可用。
4. **修改最合适的层。** 数值与身份由服务端决定；共享定义供说明与实际战斗共用；渲染插值、关节与粒子留在客户端；大厅 UI 使用独立组件与样式。
5. **看真实界面。** 自动浏览器连接实际本地服务，多窗口模拟真人、观众与不同房间；保留截图和结构化结果。动画检查实际可见的手臂、工具和轨迹。
6. **以发布物验收。** 源码检查完成后发布固定标签；下载并核对附件摘要；匿名拉取已发布镜像，在 amd64 与 arm64 环境执行双客户端检查。

## 需求会演进，文档要解释原因

- 早期要求“开局没有武器”，随后明确改为“每个人物都要有默认的普通攻击”。当前设计保留进入地图后的首次随机选卡，并额外给每个职业独立普攻；首张卡增加随机构筑，普攻和职业 Q 均保留。
- “整体透明度”最初容易被理解成画面内部透明。后续区分网页内容不透明度与原生透明窗口：普通网页受浏览器限制，桌面端提供原生窗口能力。
- “144 FPS”成为目标档位与帧调度检查要求，实际表现仍受设备、分辨率、怪物密度影响，不能把设置值当成全场景实测值。
- “AI 做完”包含多轮诊断、修复和验收。作者多次报告同一个观感问题后，AI 需要继续检查根因，不能凭一组数值断言就认为体验已经解决。

## 当前普攻问题的诊断案例

此前服务器约在动画时长的 20% 处释放攻击，并设置 95ms 上限，而可见出手曲线在约 30% 附近进入接触阶段。多个模块还可能连续更新动作标记。工具绘制采用同一握持比例与尖端偏移，不同形状的咖啡杯、拖把、扳手并不适合统一几何。

本轮把职业普攻放到独立冷却与攻击来源中，保留完整的起手、出手、收招；共享动作时长决定 30% 的释放点；为现有工具设置各自的握持与尖端位置，并增强手臂、躯干、后坐和连续轨迹。额外随机模块仍有独立伤害、冷却与特效，多模块同时触发时优先保持普攻动作连贯。

另外复现了换职业后的绘制层级问题：新建骨架默认层级为0，而角色位置未变时深度缓存不重新更新，模型可能被场景物件压住。现让新骨架继承角色当前层级，并逐职业检查实际绘制层级。
