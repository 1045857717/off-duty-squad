# 3.9性能与动作验收

2026-10-22，Windows本机、Chromium、DPR2。源代码与浏览器验收结果分别记录，帧率没有统一写成“全部144通过”。

| 场景                                                                | 平均游戏渲染FPS | 测试环境                                 | 结果                              |
| ------------------------------------------------------------------- | --------------: | ---------------------------------------- | --------------------------------- |
| 4客户端、每人4个Lv.8模块、100敌人、地图种子3900、主界面（最终样本） |          153.11 | 显式解除浏览器帧率/垂直同步限制；采样6秒 | 本样本超过144；较早样本137.72未过 |
| 同一对局的520×350低调视图（最终样本）                               |          122.67 | 相同DPR2；另采样3秒                      | 未过144；较早样本186.31超过目标   |

最终主界面压力样本P95帧间隔10.60ms。较早相同种子的完整样本为主界面137.72、小窗186.31FPS；最终样本为153.11、122.67FPS。两项严格144断言均保留，本次命令因小窗未过而以非零退出。不同时间段的战斗负载和浏览器调度会带来波动，不能只选较高样本宣称全部通过。小窗数字来自解除同步限制的实验环境，实际玩家仍受显示器、浏览器调度、硬件、分辨率和怪潮规模影响。此处不保证所有设备或所有密集场景始终144FPS。

模型没有通过降低动画更新频率来提速。全部15关节仍每帧插值；优化包括直接提交已有骨骼矩阵、移除隐形旧精灵的逐帧动作、圆形使用三角扇、圆弧按半径选取顶点，以及减少DOM布局读写。几何弦误差控制在约0.25世界像素。图集3840×3808；真实浏览器测试观察GPU提交并检查模型、坐标、透明度、视角和部件。

普通场景144档位会与独立空白页刷新基准比较，避免把游戏自己变慢后的RAF作为通过目标。最终普通场景报告在发布验收中记录；压力样本不能用普通场景成绩代替。

## 复现压力场景

PowerShell（门槛保留144，完整视口达不到时会失败，同时保存两个视口的测量和截图）：

```powershell
$env:BENCHMARK_UNCAPPED='1'
$env:FULL_ARSENAL='1'
$env:STRESS_MODULES='4'
$env:ENEMY_COUNT='100'
$env:STRESS_SEED='3900'
npm run test:stress
```

测试使用1个浏览器与3个真实Socket.IO协议客户端，自行启动服务器并使用受路径检查保护的临时数据目录，不使用玩家排行榜数据。固定种子用于复测；不设种子时继续覆盖随机地图。测试角色有存活保护，以便持续测量攻击负载；不是正常游玩难度。

## 普通场景与原生客户端

DPR2普通144档位实测142.81FPS，独立空白页刷新基准142.86Hz。显式解除同步限制的实验档位实测143.89FPS，测试强制以144作为目标（RAF回调324.75FPS）。Windows原生520×350实际对局测得143.34FPS、设备像素比1；同时经真实IPC验证透明度、置顶、鼠标穿透、隐藏/托盘恢复与F9尺寸恢复。
