# 1.1 性能测量与修复

日期：2026-10-20。环境：Windows、真实 Chromium、1440×1000 视口、单人 + AI 补给员、Chrome DevTools CPU 4 倍限速。每次采样约 8 秒。数据用于定位本机多余工作，不等同于所有电脑的 FPS 保证；AI 击败敌人的速度和测试期间场景实体数存在小幅变化。

| 指标 | 修改前 | 修改后 |
|---|---:|---:|
| 文字纹理生成次数 | 3,680 | 2 |
| 游戏实际绘制帧数 / 8秒 | 1,839 | 436 |
| 游戏帧率 | 229.8（无限制） | 54.5（目标60） |
| JS 执行时间 | 4654 ms | 1423 ms |
| 主线程任务时间 | 5836 ms | 2261 ms |
| JS 堆占用 | 16.1 MB | 10.4 MB |
| 超过 50ms 的长任务 | 0 | 0 |

这组采样中 JS 执行时间减少约 69%，堆占用减少约 35%。修改前的高帧数意味着在这台高刷新率设备上进行了大量不必要的绘制；优化目标是限制这些工作并保持可用的帧预算，不是把测到的帧数上限继续提高。

## 已修复的路径

1. Phaser `Text.setColor()` 会触发文字绘制和纹理更新。以前角色名每帧调用，现只在角色颜色实际改变时调用。这在 8 秒中消除了约 3,678 次重复生成。
2. Phaser `fps.target` 不等于渲染上限。增加显式 `fps.limit:60`，避免高刷新率环境无休止渲染。继续使用 requestAnimationFrame。
3. 游戏场景直接读取最新网络快照；React 界面以约 120ms 间隔更新，状态阶段变更立即发布。后台页面不重复刷新界面。
4. 快照之间对运动进行最多100ms的预测，并经过地图碰撞检查；平滑追赶时间由48ms缩短为28ms，降低拖影式的迟滞感。
5. 弹出小窗后卸载主页面 Phaser 渲染器，只有独立游戏窗口绘制。隐藏时主动休眠游戏循环，恢复时唤醒并清理残留按键。
6. Electron 可见但未聚焦的小窗不接受后台节流；真正隐藏后主动休眠，恢复不依赖原页面保持焦点。
7. 右下角显示实际游戏渲染 FPS，方便在目标电脑核实；设置中仍可减少环境动态效果。

## 重现

```powershell
npm start
# 另开终端：
npm run browser:install
npm run test:performance
```

`PLAYWRIGHT_BROWSER` 可指定现有 Chromium，`GAME_BASE_URL` 可指定服务器。性能测试检查固定测试环境下实际渲染帧率在40–66FPS之间、采样期间文字纹理生成不超过30次、隐藏后绘制帧数为0。浏览器独立窗口和画中画的身份交接分别由 `test:windows` 和 `test:pip` 检查。

当前没有对另一台物理电脑的 GPU、浏览器扩展、远程桌面或实际公司网络进行性能测量。
